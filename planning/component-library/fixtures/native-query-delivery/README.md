Copy App.tsx and fixture.test.tsx into a fresh pinned consumer of the existing archive; retain the accepted index/Intl bootstrap. Raw TextInput, Codon Input and ComboBox run as separate cases with one controlled owner above the native window, an empty query, the same safe-area/header/list geometry and a 120 ms cancellable result replacement. Raw/Input own their core native window; ComboBox uses its existing public presentation. Matching does not claim byte-identical composition or a replay of the original failure: the diagnostic adds ref/native-tag/key observations and uses compact current-state metadata instead of the original growing event trace in every result label. Those timing/workload differences limit conclusions from successful runs.

A 100 ms heartbeat writes only to ref storage. It never sets state, changes a value or schedules a render. Native-change/event count, callbacks, focus/selection, actual owner commits, end-editing and stable input-ref/native-tag observations use separate trace channels. Raw/Input retain public onKeyPress; ComboBox explicitly reports that public key observation is unavailable. No value/ref/event ownership is replaced or public prop widened. Native keyboard/correction defaults remain unset.

Installed inspection records the intended XCTest string and native/current-owner verdict while the field and keyboard remain focused. Only after preserving that verdict does it use Close and Export diagnostic trace to obtain heartbeat/event storage; late blur/end-edit text remains a separate diagnostic result. That export cannot repair the focused verdict. Heartbeat timestamps are JavaScript observations; a submitted synthesized string does not prove each key reached UIKit.

Run each raw/Input/ComboBox case once, in recorded order, then at most one warm application repeat of the most reduced failing case. Preserve failures and retain the same exact Release runtime/inspector identity. A preflight transport action touches no editor. The current bounded recovery and first/warm continuation is governed by the existing roadmap; do not infer authorization to cycle guests from this fixture. No Android/large-text/rotation or acceptance propagation is included. Restore/stop the retained guest and preserve prior seals.

The focused source tests cover controlled ownership and independent observation, initial native keyboard defaults, ref stability through async results and heartbeat storage without React commits. They do not simulate native IME or synthesized-key delivery. `xctest_transport.py` replays exactly one method from an explicit frozen `.xctestrun` with a chosen simulator, Developer directory and fresh evidence output directory. It needs only Python standard library and installed Xcode. It performs no build, install preflight, dependency change, guest recovery or automatic retry. It watches stdout plus native session logs, caps total and silent time, stops its own controller process group, retains incomplete results and exports completed summaries/attachments. A transport pass requires exactly one passing test plus its actual `Transport 1` owner attachment. Raw assertion failures retain their native exit status and focused verdicts.

The controller defaults allow ten minutes total and three minutes without stdout/session-log progress, configurable through `--total-seconds` and `--silence-seconds`. Give an enclosing controller enough time for the selected allowance plus result export, while respecting the overall run deadline. Short chat-tool polling intervals do not terminate the native process. These outer allowances cannot extend a timeout emitted by XCTest itself: preserve an exit65 AX bootstrap failure separately from a controller's silence/total stop. Apple's [test execution allowance](https://developer.apple.com/documentation/xctest/xctestcase/executiontimeallowance) applies to a running test; it does not document control of the runner's AX-loaded-notification wait. Keep callback/text assertions and the original focused verdict unchanged when allowing more startup time.

`startup_diagnostic.py` checks evidence for a private observer that requires and activates an app prelaunched by the host. A completed launch must report the exact bundle/PID. Readiness still requires a real completed Transport 1 callback and the same live, untraced PID/UID/birth/executable before and after. Do not treat process appearance as startup success or use this helper to relax text assertions.

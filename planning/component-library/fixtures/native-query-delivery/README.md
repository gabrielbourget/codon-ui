# Matched Query Delivery Diagnostic

Private shared TypeScript fixture for the approved [two-pass diagnostic](../../experiments.md). It is not a maintained product scene or a production text repair. Copy App.tsx and fixture.test.tsx into a fresh pinned consumer of the existing archive; retain the accepted index/Intl bootstrap. The production package, public input allowlist, dependencies and palette remain unchanged.

Raw TextInput, Codon Input and ComboBox run as separate cases with one controlled owner above the native window, an empty query, the same safe-area/header/list geometry and a 120 ms cancellable result replacement. Raw/Input own their core native window; ComboBox uses its existing public presentation. Matching does not claim byte-identical composition or a replay of the original failure: the diagnostic adds ref/native-tag/key observations and uses compact current-state metadata instead of the original growing event trace in every result label. Those timing/workload differences limit conclusions from successful runs.

A 100 ms heartbeat writes only to ref storage. It never sets state, changes a value or schedules a render. Native-change/event count, callbacks, focus/selection, actual owner commits, end-editing and stable input-ref/native-tag observations use separate trace channels. Raw/Input retain public onKeyPress; ComboBox explicitly reports that public key observation is unavailable. No value/ref/event ownership is replaced or public prop widened. Native keyboard/correction defaults remain unset.

Installed inspection records the intended XCTest string and native/current-owner verdict while the field and keyboard remain focused. Only after preserving that verdict does it use Close and Export diagnostic trace to obtain heartbeat/event storage; late blur/end-edit text remains a separate diagnostic result. That export cannot repair the focused verdict. Heartbeat timestamps are JavaScript observations; a submitted synthesized string does not prove each key reached UIKit.

Run each raw/Input/ComboBox case once, in recorded order, then at most one warm application repeat of the most reduced failing case. Preserve failures and retain the same exact Release runtime/inspector identity. A preflight transport action touches no editor. The current bounded recovery and first/warm continuation is governed by the existing roadmap; do not infer authorization to cycle guests from this fixture. No Android/large-text/rotation or acceptance propagation is included. Restore/stop the retained guest and preserve prior seals.

The focused source tests cover controlled ownership and independent observation, initial native keyboard defaults, ref stability through async results and heartbeat storage without React commits. They do not simulate native IME or synthesized-key delivery. Run the copied fixture with the consumer's native Jest preset, ESNext/no-DOM strict types, shared lint and formatting before freezing maps and installed bytes.

`xctest_transport.py` replays exactly one method from an explicit frozen `.xctestrun` with a chosen simulator, Developer directory and fresh evidence output directory. It needs only Python standard library and installed Xcode. It performs no build, install preflight, dependency change, guest recovery or automatic retry. It watches stdout plus native session logs, caps total and silent time, stops its own controller process group, retains incomplete results and exports completed summaries/attachments. A transport pass requires exactly one passing test plus its actual `Transport 1` owner attachment. Raw assertion failures retain their native exit status and focused verdicts.

```sh
python3 xctest_transport.py --xctestrun /absolute/frozen/Build/Products/Tests.xctestrun --device SIMULATOR_UDID --method CodonPrimitiveTrialTests/CodonPrimitiveTrialTests/testTransportPreflight --developer-dir /Applications/Xcode.app/Contents/Developer --output /absolute/new-evidence/preflight
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s . -p test_xctest_transport.py -v
```

For this pinned lab, simulator boot completion alone does not prove XCTest readiness. Recovery records must keep cold framework/installer work separate from test execution. If an explicitly authorized run needs a runner preinstall, install the unchanged `CodonPrimitiveTrialTests-Runner.app` under its own fixed bound before invoking this helper; record its identity, elapsed time and optional direct process counters. Do not require installer PID discovery to start XCTest, infer activity from process presence alone, or enable Xcode test repetition flags. Validate the actual callback warm and after shutdown/reboot before resuming text cases. These instructions do not authorize service resets or guest creation outside the roadmap's current bounds.

`lldb_diagnostic.py` provides session-local settings and proof checks for an explicitly authorized private LLDB investigation. Bind the target's PID, UID, executable and birth identity before attachment; require real register/instruction-byte reads, successful detach and the same resumed process afterward. Printed command echoes cannot pass those checks. The profile defers symbol/script discovery and disables the debugger's BoundsSafety instrumentation-runtime discovery plugin for that LLDB session; it does not change the application's compiled checks, signing or global debugger configuration. These settings do not guarantee a fast attach: native stack samples still show image/symbol work during attachment.

Keep target expressions and native breakpoints outside the basic attachment proof. Any permitted tracing is a separate instrumented condition with its own bounds and original focused assertions. Accept NSString formatter output only when it is a quoted string, and validate formatter behavior before using it during a trace. An offline expression syntax check does not establish live debugger evaluation or native text delivery. The helper grants no additional replay, guest-recovery or signing authorization.

`startup_diagnostic.py` checks evidence for a private observer that requires and activates an app prelaunched by the host. A completed launch must report the exact bundle/PID. A timed-out launch retains its failure; a uniquely owned app born after that invocation may be considered without another launch, using `new_app_after_launch`. Readiness still requires a real completed Transport 1 callback and the same live, untraced PID/UID/birth/executable before and after. Replacement processes, missing state and a passing controller without callback proof fail closed. These helper checks are unit-tested; the host-prelaunch startup contrast has not passed native validation. In its bounded trial, simctl launch hits 90 seconds before XCTest starts, although a matching app process is found later. Do not treat process appearance as startup success or use this helper to relax text assertions.

Xcode can report one failed item when its runner aborts before the selected method starts. `completed_method_verdict` requires an actual single pass or a failure identifier matching the selected method; a synthetic runner-bootstrap error does not count as a completed method verdict. Failed input assertions retain their original failure and exit status. Preserve executed runner source and original receipts when applying corrected classification to an existing result; write the interpretation separately rather than rewriting historical evidence.

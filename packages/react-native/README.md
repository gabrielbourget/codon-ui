# @codon-ui/react-native

Private native-owned Codon foundation for the Expo SDK 57 / React Native 0.86.3 / React 19.2.3 laboratory. The package exports native Text, PlaceholderText, Avatar, Tag, Link, ThumbnailImage, ThumbnailShowcase, Button, ToggleButton, ToggleSwitcher, Switch, Checkbox, CheckboxGroup, Input, TextArea, Radio, RadioGroup, NumberInput, Stepper, Slider, FormField, TypeaheadSearch, Select, ComboBox, ListBoxItem, Modal, AlertDialog, LinearProgress, Meter, CircularProgress, Counter, Indicator, LineSegment, CircleLoader, LaggingLinesLoader, standalone CarouselCloseButton, the theme/overlay providers, hook and public types. Further component families follow the compatibility roadmap; closer owner visual review accompanies application feature integration.

```sh
pnpm -F @codon-ui/react-native build
pnpm -F @codon-ui/react-native typecheck:contracts
pnpm -F @codon-ui/react-native test --runInBand
```

Metro's react-native export resolves canonical TypeScript source; types and compiled imports use dist. Build before checking consumer types. React and React Native are exact lab peers; Expo is owned by the consumer. The native package has no DOM, React Aria, Expo or CSS runtime imports.

NativeFloatingLayerHost owns an explicit full-size container per native window, with an actual native View ref, original onLayout event and native outer-container styles. Put application content layout in its own child View. Modal/AlertDialog/Select windows own local hosts automatically; NativeOverlayProvider still coordinates their existing single window chain and native readiness/dismissal barriers. Host-local floating layers isolate the background while modal and retain background interaction while nonmodal. Back/accessibility escape target the eligible floating child before the containing window; closed, covered and retired library handlers cannot act. NativeDialogTrigger and ClickPopover are still under construction and are not public exports yet.

The required native portal peer is exact react-native-teleport1.2.2. Install/link it and rebuild Android/iOS native products. Both local x86_64 Release products compile/link Teleport; installed reparenting, clipping, press, accessibility and focus acceptance remain open. Native focus/key feature flags remain unchanged and iPhone signing remains deferred.

NativeFocusView is a source-owned native View host for explicit keyboard focus, with the actual View ref, normal native styles/props and no additional layout wrapper. It defaults to focusable; focusable=false or tabIndex=-1 blocks keyboard focus requests. focusNativeTarget(ref.current) and blurNativeTarget(ref.current) request keyboard focus on a live NativeFocusView or a registered core TextInput. Their boolean result means the request was admitted, not that native focus completed; onFocus/onBlur acknowledge actual native changes. Plain core Views are not portable focus targets. Generic View.focus retains its upstream behavior, and no helper changes a controlled editor value or requests screen-reader focus. Linking this package's new native sources requires a consumer rebuild; existing recorded native binaries do not contain them.

Native default capture belongs to the private declarative key policy and is reported in nativeDefaultHandled; asynchronous JS preventDefault cannot undo platform handling. NativeFloatingLayerHost now binds a private native key scope in its existing root, with no extra native layout wrapper. Declared target/modifier/editable/composition rules consume owned defaults natively; JS admits the original event only after the actual window epoch and policy revision are acknowledged. Replacement, disablement, window loss and unmount retire old packets and held keys. Escape requests the current floating child, including protected/transitioning shields; a declined controlled close remains open. NativeFocusView reports observed focus visibility, and tooltip focus bindings use native metadata or observed current-window keyboard input, with unknown focus alone excluded. Fresh matching native products are required for this new scope revision; earlier raw-host products do not certify it. Owned-control migration, native hover delivery, tooltip description and viewport/scroll binding, plus installed keyboard/hover acceptance remain open. HoverPopover itself has tooltip semantics: touch entry is ignored, with no automatic tap/long-press trigger; use an explicit ClickPopover action for essential touch-accessible information.

## Recommendation

Evaluate the published RN Primitives packages in a bounded, isolated compatibility trial before migrating production package source. Dialog and AlertDialog are plausible headless foundations, with documented adapter work. Select 1.5.2 is not a compatible replacement for Codon's current controlled-open contract. Preserve the existing implementation and its tests as the comparison baseline. Adopt a primitive only when it preserves the agreed behavior and removes meaningful library-owned interaction infrastructure.

Use npm packages behind Codon's facade rather than copying and maintaining an upstream fork. Do not adopt React Native Reusables, NativeWind, Uniwind or another theme system for this trial. RN Primitives' native source uses ordinary React/React Native components; the screened archives contain no Swift, Objective-C, Kotlin or Java implementation or native installation script. Shared TypeScript/TSX remains the default for Codon adapters. Device-specific behavior must address an observed platform difference; a custom native module requires a separate architectural decision.

**Approval covers the trial, not a blanket migration of all three components.** A successful trial returns a concrete migration diff/contract recommendation; a failing trial returns the exact mismatch without another dependency, source fork or weakened contract. Production dependency additions and the final adapter/host design remain a subsequent decision. The owner's clarification explicitly preserves controlled values: Select value control is supported; its missing declarative open-state input is a separate contract difference.

## Evidence And Its Limits

The [official project](https://rnprimitives.com/) describes style-free primitives; its [Dialog](https://rnprimitives.com/dialog/), [AlertDialog](https://rnprimitives.com/alert-dialog/) and [Select](https://rnprimitives.com/select/) documentation explains the compound API and portal setup. Evaluation used actual npm publisher archives and declarations, not accessibility marketing as acceptance evidence. The reference TypeScript tree is pinned to upstream [`1bebe66b12e7ddd3c313226e0bc2ee02b6e78ab4`](https://github.com/roninoss/rn-primitives/tree/1bebe66b12e7ddd3c313226e0bc2ee02b6e78ab4), dated 2026-08-08. npm metadata lacks gitHead, so this reference is not proof of source-to-publication provenance; the exact archives and integrity checks identify the evaluated runtime.

Eight isolated behavior probes pass using the published JavaScript, real React 19.2.3, the existing test renderer and real Zustand 5.0.15, with mocked React Native hosts/measurement/BackHandler. They establish repeated controlled Dialog rejection, direct Alert action ordering, two asChild ordering/throw cases, host-location context behavior, closed Content Back subscription, ignored Select open state and disabled-trigger forwarding. A strict TypeScript 5.9.3 probe passes six positive and four negative cases under the existing native ESNext/no-DOM settings, retaining the existing skipLibCheck setting. Negative cases reject Select open/defaultOpen, null selection and numeric primitive values. These are source-level compatibility checks, not an installed candidate build, Metro resolution proof, screen-reader certification or device acceptance.

Private evidence is retained at `/Users/gabrielbourget/.codex/visualizations/2026/10/11/01a12cc2-8c0c-71f1-b7aa-f055be011117/native-rn-primitives-evaluation-2026-10-15`. | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Styling                | Native primitives accept RN props/styles and asChild composition.                                                                                                              | Keep all Codon themes, type/geometry/order props, state styling, validation and style precedence in adapters. No styling-library dependency is needed.                                                                                                                        |
| Dialog state           | Root supports open/defaultOpen/onOpenChange. Rejected controlled closure can be requested repeatedly.                                                                          | Preserve isOpen/defaultOpen/onOpenChange and fixed ownership validation through the wrapper. Keep the public Codon name Modal; do not add a second public Dialog synonym.                                                                                                     |
| Dialog dismissal       | Overlay supports closeOnPress; Content installs BackHandler and accessibility escape handling.                                                                                 | Independent backdrop/system guards and active-leaf ownership remain explicit adapter/host responsibilities. A generic false request does not identify its dismissal source.                                                                                                   |
| Alert actions          | Direct Action/Cancel requests closure before invoking its own onPress callback.                                                                                                | Use asChild with the business callback on the child Codon Button: the evaluated Slot runs the child first, and a synchronous throw prevents subsequent primitive closure. Preserve labels, no-awaited-promise behavior and callback-free external dismissal.                  |
| Select state           | Root controls value but owns open in internal useState; it accepts neither open nor defaultOpen. Trigger refs expose imperative open/close.                                    | Codon's isOpen/defaultOpen and declined/repeated requests have no equivalent public state input. Imperative synchronization does not provide a veto before internal mutation. Defer migration rather than silently changing this contract or reaching into context internals. |
| Select values          | Upstream selection is { value: string, label: string } or undefined.                                                                                                           | Retain Codon's collection normalization, stable numeric/string key encoding, null facade, dynamic label lookup and disabled-key/read-only guards. | Disabled Select        | In 1.5.2, Trigger's default disabled=false overrides Root's disabled for the native Pressable even while accessibilityState reports disabled.                                  | Explicitly pass disabled to Trigger and verify that both native interaction and semantics agree. The probe reproduces the source discrepancy; this is not a reason to drop Codon's guard.                                                                                     |
| Lists/presentation     | Select Content positions relative to a measured trigger; native Viewport/scroll-button helpers do not supply virtualization.                                                   | Full-screen presentation, explicit Close, safe areas, selected-row positioning and variable-height FlatList support remain Codon work. Anchored selection/search is outside this trial's public contract.                                                                     |
| Portal/context         | Portal stores React elements in a module-level Zustand store. The feature Portal re-provides its own primitive context, while arbitrary caller context resolves at PortalHost. | A root host can change caller-local theme/application context. The probe observes the host value, not the caller value. Re-providing Codon theme alone does not preserve arbitrary application providers.                                                                     |
| Portal isolation       | Hosts select entries by name from a module-global map.                                                                                                                         | A provider-scoped unique host name and one installed portal identity are required; a shared default name is not per-provider isolation. Portal order alone is not an active-chain or teardown policy.                                                                         |
| Focus                  | Shared hooks schedule accessibility focus/restoration after 50 ms using findNodeHandle/setAccessibilityFocus.                                                                  | This is not readiness-aware initialFocusRef/restoreFocusRef or selected virtual-row focus. Check the pinned Fabric runtime and avoid competing focus owners; the native Content API provides no focus-timer opt-out.                                                          |
| Closed/covered content | Content registers its Back handler even when its render subsequently returns null for closed state.                                                                            | Mounting/coverage strategy must prevent hidden content consuming Back. A parent must retain local state while covered and ordinary full closure must still unmount it.                                                                                                        |
| Window/layout          | Native primitives render Views/Pressables; their Portal is not core RN Modal presentation.                                                                                     | They do not inherently supply safe areas, keyboard avoidance/reveal, orientation measurement, window lifecycle or background accessibility/pointer isolation. ## Proposed Host And Adapter Trial

Compare two arrangements in an isolated consumer, without changing Codon's exports or removing current source:

1. **A provider-owned root portal host.** Use a stable provider-specific name and explicit Codon theme/content ownership. This could remove serial native-window presentation bookkeeping because the layers share an application window. Treat that reduction as an inference to test, not an established result. Require caller-context/local-state, background accessibility, active-leaf Back/focus, owner removal and layout tests. Generic caller-context preservation is a known unresolved mismatch. Do not call a manual bridge of the fixture's one context a general solution or introduce a new public host/context API without another proposal.
2. **Primitives within the existing caller-owned native window.** Render the primitive parts inline under the current source context and retain the current host. This preserves a credible context baseline, but likely retains most window lifecycle/keyboard/focus coordination. Measure what behavior it actually replaces. Do not adopt merely to add another abstraction while retaining the same custom engine and a second set of focus/Back owners.

For either arrangement, keep Modal/AlertDialog/Select public names and approved props, refs and labels; keep the palette/default-theme file byte-identical; preserve the starter Modal, six AlertDialog statuses/custom marks, full-screen Select and all style slots. The trial must identify genuine conflicts instead of relabelling a new presentation as equivalent. Existing simple controls and their files stay outside scope. Keep touched adapters consistent with the React package's thin rendering/style-helper separation and the shared ESLint/Prettier/TypeScript conventions, with T-prefixed types, arrow functions and constants-derived unions.

Select remains a negative compatibility case in the trial. A supported upstream controlled-open implementation would need a newly screened exact release; a deliberate Codon API simplification would need a separate proposal explaining consumer effects. An imperative facade, hidden context mutation, vendored fork or polling loop is not an approved substitute. Dialog/AlertDialog adoption also depends on coexistence with the unchanged core-native Select window, including both directions of nested use.

Upstream alignment is a legitimate alternative to preserving every custom contract. For example, removing Select isOpen/defaultOpen while retaining controlled selected values would match the evaluated root more closely; requiring overlay-consumed providers above the host would address ordinary root-provider use while explicitly changing caller-local context behavior. These are Codon API/ownership tradeoffs, not inherent React Native requirements. The trial should inventory affected native call sites and present any worthwhile simplification concretely; it must not rewrite fixtures to conceal a contract change. Neither simplification is approved by this packet.

The intended adoption sequence after a go decision is Modal through Dialog first, AlertDialog through the same proven host second, and Select only after its state/presentation decision. Each migration would retain Codon's public styling facade, remove the superseded behavior paths in the same coherent change and keep independent contract tests. Final acceptance would use a new immutable archive/frozen external consumer, both Metro graphs and installed Release apps with actual source/binary identities. This sequence describes the destination; the unresolved host and API choices prevent authorizing that production migration as a mechanical task today.

## Bounded Execution And Commit Cadence

Use two logical passes/commits for the approved trial and its decision receipt, following the prerequisite review/documentation commit. Do not interpret this packet as permission to replace production implementations immediately.

1. **Isolated compatibility fixture and dependency proof.** Create a fresh consumer from the immutable Codon 13f267c archive and the existing pinned Expo/RN lab tuple. Add only the four exact trial dependencies and their reviewed declared closure, freeze its own lockfile, retain its baseline graph and prove one React/RN/safe-area/portal identity. Reuse Codon styles and public-contract scenarios. Exercise both host arrangements, callback composition and the explicit Select incompatibility. Run focused mock/type cases, both production Metro exports/maps and a byte/hash theme comparison. Record graph/size deltas and stop on a package/tooling/host requirement beyond this packet. Keep reusable diagnostics and the first receipt as one reviewable repository step; retain generated consumers/binaries in the private evidence packet.
2. **Installed gate and adoption decision.** Build/install/hash Release Android and iOS simulator apps one guest at a time, using existing local tooling and no signing. Check ordinary/large text, portrait/landscape, focused Input/keyboard and complete actions; parent-local state/context through Modal → Modal, Modal → AlertDialog and Modal ↔ Select; theme/style/ref behavior; backdrop versus Back guards, repeated controlled rejection, action ordering/throws, ancestor closure/replacement, owner teardown and removed focus targets. Include an instrumented selected offscreen Select row, zero disabled activation and hidden-background accessibility hierarchy checks. Restore/stop the task guests. Report which custom behavior can actually be removed, what remains and exact failed gates. Commit the decision/roadmap receipt separately. Physical VoiceOver/TalkBack, touch/IME/ARM and closer owner visual review remain in the application/device lane; iPhone signing stays deferred.

The trial has a go result only if a concrete host/adapter preserves the current public contracts, styling/palette and essential caller-state/context behavior with a meaningful reduction in owned interaction infrastructure. Source probes alone do not satisfy that gate. If only the existing custom host plus competing primitive behavior works, recommend retaining the current implementation for these overlays and re-evaluating upstream later. A selective Dialog/AlertDialog go does not imply a Select go. The next production migration packet must name the chosen host, exact graph, source deletions, retained responsibilities and any proposed contract change before approval.

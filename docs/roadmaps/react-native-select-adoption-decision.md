# Native Select — Adoption Decision

Status: **Accepted on 2026-10-15; current Codon implementation retained**. Tracking item: **RN-SELECT-ADOPT-01**. Prepared on 2026-10-15 against `b8bf5a9b205443cb080f99c67cdd7e3e7ac7dd04`. Owner/acceptance: Gabriel Bourget. Responsible contributor: this Codon chat. Gabriel approved the [three-pass acceptance/handoff run](react-native-select-acceptance-pass.md) and logical commits. This document authorizes no installation, production migration or enduring upstream fork.

## Recommended Decision

Retain Codon's current Select, collection/state helpers and virtualized ListBoxItem composition for the next roadmap milestone. Decline production adoption of the evaluated RN Primitives Select and the private fixed-source candidate. Use React Native Reusables as a source reference and keep published primitives eligible for other components when their contracts fit. Finish Select's pending installed acceptance, then prepare the next component-family proposal. Select adoption should have a recorded disposition rather than an indefinite sequence of speculative trials.

This is a production-adoption decision about the evaluated candidates. Current Codon Select supports both controlled selected values and controlled popup visibility. Preserve `value`/`defaultValue`/`onChange`, `isOpen`/`defaultOpen`/`onOpenChange`, caller rejection of requests and all existing style/collection contracts. Shared React Native TypeScript remains the default. Palette changes, application-feature visual sign-off and iPhone signing retain their deferred disposition.

Official npm metadata rechecked on 2026-10-15 still identifies [Select 1.5.2](https://registry.npmjs.org/@rn-primitives/select/1.5.2) and [Portal 1.5.3](https://registry.npmjs.org/@rn-primitives/portal/1.5.3) as the latest stable releases. The current source remains pinned to [`1bebe66b12e7ddd3c313226e0bc2ee02b6e78ab4`](https://github.com/roninoss/rn-primitives/tree/1bebe66b12e7ddd3c313226e0bc2ee02b6e78ab4). The [native Root implementation](https://github.com/roninoss/rn-primitives/blob/1bebe66b12e7ddd3c313226e0bc2ee02b6e78ab4/packages/select/src/select.tsx) and [native types](https://github.com/roninoss/rn-primitives/blob/1bebe66b12e7ddd3c313226e0bc2ee02b6e78ab4/packages/select/src/types.ts) are the authority for the popup-state finding; selected-value control is a separate supported capability.

Collection normalization, numeric/string key identity, null selection, current-label lookup, disabled/read-only guards, style validation, variable-height virtualization and selected-row positioning remain Codon work under the attempted adapter. Some retained work is normal for a styled facade; the deciding problem is the combination of an unapproved compatibility fork and no demonstrated worthwhile simplification. The shared 435-line overlay inventory also serves Modal/AlertDialog and cannot be counted as savings from migrating Select alone. A future adoption proposal needs a concrete before/after responsibility diff, not a promise based on component size.

## React Native Reusables Reference

Rechecked source is unchanged at [`385834c2196f8a303cbc9057d1ac768f3bde0a3b`](https://github.com/founded-labs/react-native-reusables/tree/385834c2196f8a303cbc9057d1ac768f3bde0a3b). Its [Select wrapper](https://github.com/founded-labs/react-native-reusables/blob/385834c2196f8a303cbc9057d1ac768f3bde0a3b/packages/registry/src/nativewind/components/ui/select.tsx) forwards a named `portalHost`, uses react-native-screens FullWindowOverlay on iOS, and uses a React Fragment on other platforms. Its [Dialog wrapper](https://github.com/founded-labs/react-native-reusables/blob/385834c2196f8a303cbc9057d1ac768f3bde0a3b/packages/registry/src/nativewind/components/ui/dialog.tsx) follows the same host pattern. Codon can learn from these compositions while retaining its own theme roles, state styling and public facade; NativeWind/Uniwind, animations and icon dependencies are not prerequisites for borrowing the idea.

A named host placed within the required caller context is a candidate for preserving that context. FullWindowOverlay moves native iOS presentation under the window; it does not itself transport arbitrary React context or establish Android modal behavior. The [Screens documentation](https://github.com/software-mansion/react-native-screens#fullwindowoverlay) describes that iOS scope. Direct local rendering through FullWindowOverlay could avoid a React portal altogether, but that is an untested simplification to evaluate, not established Codon behavior.

Source screening of the compatible published `react-native-screens` **4.26.0** identifies an iOS wrapper with children and an unstable accessibility-container option, without public native shown/dismissed callbacks. Codon's current registry uses readiness and dismissal barriers to admit one active chain and restore focus. A replacement must demonstrate equivalent ownership, hit testing, accessibility isolation, teardown and handoff rather than substituting a delay for a lifecycle guarantee. Android would still need a presentation strategy. These are reasons to defer a Select-only host experiment until it offers a concrete integration benefit.

## Deferred Host Candidate And Revisit Triggers

Expo 57.0.26's installed bundled-native-modules manifest recommends `react-native-screens ~4.26.0`. The screened exact candidate is [4.26.0](https://registry.npmjs.org/react-native-screens/4.26.0), published 2026-07-10, MIT, with React Native peer `>=0.84.0` and declared `warn-once ^0.1.0` / `react-freeze ^1.0.0` dependencies. Its archive SHA-256 is `f753b4c20e742add16c0e62b09bd112177822721b1ff9c38d71abab76528382f`; its declared compatibility and release age fit the existing Expo/RN 0.86.3 lab. This is metadata/source screening, not an installed compatibility result. Latest Screens 4.30.0 is not selected as an incidental upgrade.

Revisit adoption when an eligible published Select provides native declarative popup control and verified Portal identity, or when a shared overlay integration presents a measured opportunity to remove machinery across multiple components. A host-only trial may also be proposed for a concrete iOS stacking/context defect. It would first specify local/named-host placement, published package pins and the consumer peer/runtime policy, one interaction owner, native readiness/removal evidence and Android behavior. Public imports, normal native linking and app rebuilds would be required; a static import cannot be called an optional peer without a supported resolution boundary. Vendored native code in Screens is distinct from writing custom Codon Swift/Kotlin, and any new native dependency still requires approval.

## Acceptance And Roadmap Effect

The [controlled-text isolation receipt](react-native-controlled-text-sequence-receipt.md) retains an intermittent callback-until-blur failure and the older wrong-native-text evidence; [RN-TEXT-01](react-native-controlled-text-runtime-follow-up.md) owns the next runtime/driver investigation. That issue is not the sole reason for declining Select migration. Track its actual effect on a Select interaction if reproduced, without launching another general typing matrix or weakening controlled values.

Owner acceptance of this retention decision closes the adoption-choice checkpoint. Installed Select/overlay acceptance remains a separate open gate under the [three-pass proposal](react-native-select-acceptance-pass.md); physical VoiceOver/TalkBack/touch/IME and closer application-feature visual review stay deferred. New public API, dependencies, host architecture, publication and registry/CLI changes require their own proposal. The next family continues the library-first approach through fresh source/primitive-fit screening rather than inheriting a blanket rejection of RN Primitives.

The approved [three-pass receipt](react-native-select-acceptance-receipt.md) now records focused installed Select acceptance on both platforms and one localized positioning-budget fix, without a new dependency or palette change. The [next proposal](react-native-searchable-selection-pass.md) follows the dependency audit into PlaceholderText and searchable selection. RN-TEXT-01 and broader physical/catalogue acceptance remain owned separately.

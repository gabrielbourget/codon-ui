## TextArea

Recommend a native-owned core TextInput with `multiline` fixed true and its real TextInput ref. Reuse the existing Input contract's value/defaultValue, onChangeText, native change/focus/blur/selection events, keyboard options, text scaling, disabled/read-only guards, native color validation and style precedence. Keep the existing Input implementation and its single-line contract unchanged. Require a nonempty accessibilityLabel or aria-label, with native-label precedence; a placeholder does not supply its accessible name.

Use a default editor height of **96 native logical units**, caller-overridable through native height/customStyles/final style. This is a bounded scrolling editor rather than automatic growth. Preserve native multiline scrolling and expose onContentSizeChange as its native event without hidden resizing. numberOfLines remains a platform hint rather than a cross-platform size guarantee. Align Android multiline text to the top. Default Return behavior is newline; retain explicit submitBehavior for hosts that choose submission. Omit the deprecated blurOnSubmit alias, single-line clearButtonMode and secureTextEntry from this counterpart. [RN 0.86 TextInput](https://reactnative.dev/docs/0.86/textinput) defines these native events and platform boundaries.

Preserve isDisabled/isReadOnly rather than editable/readOnly aliases. Block mutation callbacks while either guard is active; only disabled owns disabled presentation and blocks focus. Keep native events and selection behavior rather than translating them into DOM events. Hosts own validation messages, transformations and persistence. The scene's explicit submit fixture must read final text from the native submit event, as the maintained Input fixture already does.

Preserve small/medium/large as b11/b10/b9, geometry, native width/height, enableFocusStyle and offsetFocusRing. Error → warning → success controls border presentation only. Root customStyles precede final style; callbacks receive focused/disabled/read-only/invalid and the post-custom defaultStyle. Use existing control background/foreground/placeholder, validation, focus, spacing, radius and typography roles without adding fields or changing values. Font scaling stays enabled by default with no library-imposed cap. DOM forms/classes/refs, CSS resize controls and arbitrary children are excluded; no resize constants are exported.

Export TextArea, TextAreaProps, the TNativeTextArea props/ref/size/render/style-state aliases, TEXTAREA_SIZE\_\_SM/MD/LG and AVAILABLE_TEXTAREA_SIZES as const. Use existing private control/color helpers; do not broaden this pass into an Input refactor or new shared field framework.

## Radio And RadioGroup

Recommend a View-backed Pressable Radio controlled by the nearest private RadioGroup context. Radio requires a group and a string value; empty string remains a valid value. Values identify unique choices within that group. Hosts must supply unique stable member values; duplicate values are unsupported input. This pass does not introduce child registration, arbitrary React-child discovery or a public collection framework. Render children normally through context without walking or cloning them, and isolate nested groups.

RadioGroup owns controlled value or initial defaultValue, each string or null, plus onChange(nextString). Undefined value selects uncontrolled mode; null explicitly clears controlled selection. Initialize defaultValue once. Activating an enabled, different member requests exactly one change. Reselecting the current member is quiet. Controlled rows update only when the parent echoes value. Removing a member leaves the requested value intact, with no automatic callback; reinsertion restores its selected presentation. Radio has no independent isSelected/defaultSelected or selection onChange props.

Group isDisabled/isReadOnly guards own all descendants. A member's isDisabled can further restrict availability; explicit false cannot override a disabled group. Read-only permits inspection/focus without mutation and has no disabled opacity. Apply disabled opacity once per member, rather than multiplying group and child opacity. Preserve native Pressable observation callbacks through the existing interaction helper, with blocked activation suppressed. Choosing the current row may still produce its native press observation without a group selection change.

Require explicit accessible names for group and members through accessibilityLabel/aria-label. Own radio role and checked/disabled state on each member; reject conflicting role/checked/disabled aliases. Keep the radiogroup wrapper nonaccessible so its children remain separate targets, retaining its group-role/name metadata without collapsing descendants. The [RN 0.86 accessibility contract](https://reactnative.dev/docs/0.86/accessibility) supplies the radio/radiogroup roles and checked/disabled fields; installed hierarchy checks must capture the resulting traits, while later physical review verifies announcements. Hosts supply localized read-only, required and validation explanations. DOM form validation, name submission, React Aria state/slots and web Arrow/Home/End/typeahead coordination are excluded.

Preserve the canonical 20-unit visual shape, rounded/round/orthogonal geometry, five existing action orders, optional native ColorValue and focus-ring options. Reuse the existing native Checkbox/Switch color recipe; explicit color owns shape border/selected fill and does not recolor the label. Selected fill remains stable during hover/press. Default unselected/hover/pressed and selected colors use existing native roles, with no CSS color-mix evaluation or palette additions. The web wrapper's color branch primarily suppresses its order class; native color behavior is an explicit counterpart contract rather than a web source correction. Draw the shape with native Views, without SVG or animation dependencies.

Root customStyles/final style own the radio target; customShapeStyles owns only the mark. Primitive, array and Fragment labels use the existing owned Text composition and preserve text scaling. Authored elements remain authored; custom content must stay decorative within the one interactive root. Automatic target minima remain 44 points on iOS and 48 dp on Android. Explicit constraints and clipped-parent hit-slop limits retain the existing native exception.

RadioGroup defaults to vertical flow with two spacing units between members; horizontal flow wraps within available width. Its customStyles/final style own the container, with callback state value/disabled/read-only and post-custom defaultStyle. Expose the real native View refs, Radio/RadioGroup Props aliases, TNative props/ref/render/style-state aliases and RADIO_GROUP_ORIENTATIONS as const with its derived orientation type. Member callbacks expose owned selection/pressed/hovered/focused/disabled/read-only flags, without React Aria state or focus-visible promises. Group children remain ReactNode, following the existing native CheckboxGroup pattern.

## Why NumberInput Follows Separately

NumberInput composes React Aria NumberField, Group, Input and increment/decrement slots; its behavior comes from inherited numeric state rather than merely selecting a numeric keyboard. Current Codon consumers include pagination PageInput, numeric filter arguments and numeric range arguments. PageInput supplies min/max and a 30-pixel height, which cannot be copied into an unconstrained native touch contract.

Before implementation, specify the editable draft versus committed number, empty/partial input, sign/decimal/digit handling, locale/format options, bounds/step/rounding, blur/submit and controlled-echo behavior. Increment/decrement labels, adjustable accessibility, repeat behavior and independently usable touch targets also need concrete choices. A raw Number(text) conversion would not preserve the inherited contract. The next NumberInput proposal must choose parsing/formatting ownership and any additional dependency explicitly; this proposal adds no numeric runtime or approximate NumberInput API.

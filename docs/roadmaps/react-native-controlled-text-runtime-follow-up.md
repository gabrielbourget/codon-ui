Its same-binary repeat passes. The older trial also records a different failure, with incorrect text already present in raw native change events. Keep both observations and their identities; the new focused success does not erase the older corruption.

## Suggested Bounded Diagnostic

1. Reuse the pinned consumer/runtime and the single raw TextInput fixture. Compare one fresh guest startup with one warm application restart, keeping default input settings and the same unpaced phrase. Preserve actual test order and application/guest identities. Add a ref-only JavaScript heartbeat and retain key, native-change, selection, callback, owner-commit, blur and end-editing observations. The heartbeat must not update controlled state or the visible tree. This separates an unresponsive JavaScript interval from a responsive interval in which the expected native change is absent. Limit each startup condition to one run; a passing rerun retains the original failure.
2. If the focused divergence reproduces while JavaScript remains responsive, inspect the native field's marked-text/composition and change-dispatch state using the installed Apple debugging tools. Keep this read-only lab instrumentation separate from shipped components. Compare the delivered event stream with the driver's intended keys and observed native value. If a wrapper defect is demonstrated in a matched single-field comparison, prepare a focused wrapper fix with a regression test; if raw TextInput reproduces it, prepare an upstream/runtime report draft with the exact version, minimal shared TypeScript and actual trace. Publishing a report, upgrading dependencies or changing system keyboard preferences remains a separate decision.
3. Return an attributed repair proposal or an explicit runtime/IME/driver limitation. Preserve default-contract failures even if a diagnostic setting or focus change completes the value. Retain authoritative caller state, native event-count protection and current public defaults. Re-run only the affected default scenario and its matched control after an approved fix.

The trigger is a continuing automated default-contract block or reproduction in an application form. Physical IME/touch review stays in the deferred application-integration lane.

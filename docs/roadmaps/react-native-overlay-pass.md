## Why This Family Follows

The [overall M2 checkpoint](../../../wavemap/planning/mobile-app/roadmap.md#m2-slice) requires difficult table/date/selection/overlay compositions before wider propagation, and its [family sequence](../../../wavemap/planning/mobile-app/roadmap.md#m2-catalogue) requires dependent leaves before composites. The common editing controls now exist. Recommend Modal and AlertDialog next, with narrowly scoped ownership shared with the already implemented Select window, rather than treating the manifest's display order as an implementation sequence.

This pass establishes a modal/confirmation foundation for later searchable selection and date/table work. It does not complete those difficult representative cases or select a calendar, table, sheet, anchored-popover or menu architecture. Modal and AlertDialog would advance source implementation from twelve to fourteen of 53 counterparts after their own gates pass. A native ownership provider is support infrastructure, not an additional catalogue component. Production Wavemap integration remains later work.

## Ownership And Dependencies

Recommend core React Native Modal/View/ScrollView/Pressable/Text, existing Codon Button/Text, existing color/target helpers and the already pinned safe-area peer. Add no runtime or peer dependency, Expo module, portal package, native module, Intl change or toolchain upgrade. Source remains native-owned in packages/react-native; apps/native-showcase owns synthetic fixtures and outer app layout. No registry/CLI, publication or deployment work is included.

Independent core-modal wrappers would keep the public surface smaller, but leave shared chain admission, readiness and focus ownership with each caller, including Select interoperability. A single portal host could arbitrate arbitrary sibling layers but introduces a different rendering/context contract and possible dependency. Platform Alert cannot retain this wrapper's custom content, icons and style slots. Recommend the scoped provider below for the declared nested-chain job, with native proof before accepting the pattern for further families.

Propose one new public NativeOverlayProvider with children-only props. It owns a private registry of requested/presented/closing overlay instances for one application root, without public registration or dismiss-all APIs. Modal and AlertDialog require it; nested providers are rejected rather than creating competing owners for the same windows. It does not move React children, render a portal host, walk/clone arbitrary children, own theme/insets, install a process-global singleton or coordinate product navigation. Native windows remain at their declarative React locations so local theme and arbitrary caller contexts are preserved.

Select keeps its current public API and standalone behavior without a provider. Inside the provider it participates in the same private lifecycle/parent registry as a leaf window, including its known trigger focus target. Its full-screen list, typed keys, safe-area ownership and selection rules remain unchanged. This bounded internal adaptation is necessary to prove Select inside Modal rather than introducing an independent dismissal owner. It requires focused Select regression and installed checks; this is not a general Select rewrite.

## Window Chain And Lifecycle Contract

Support one active root-to-leaf chain per provider, with nested overlays declared inside an ancestor's content. Simultaneously requested sibling branches or unrelated roots are unsupported input and produce a contextual error; arbitrary sibling stacking/z-index arbitration is excluded. Serialize a root replacement after the preceding root is requested closed. Present a child only after its parent reports native onShow. Only the active leaf may process backdrop, system-close or accessibility-escape requests. Parent content stays mounted while covered so owner-held drafts, selection and scroll state survive a child window. Existing field policies remain in force: NumberInput can legitimately normalize/commit its raw draft when focus leaves, rather than the overlay overriding commit-on-blur behavior.

An ancestor closing gates descendant presentation immediately and retires windows deepest first. It does not invoke descendant cancel/confirm actions or invent business callbacks. Controlled descendants remain caller-owned; hosts must update their own open values if they should not reopen with a later ancestor. Ordinary closed content is unmounted, matching the web overlay lifecycle; drafts that must survive complete closure belong outside that content. Unmount/provider disposal cancels pending presentation and focus work, with no reopening or callbacks from stale work.

iOS dismissal completion uses native onDismiss. An already admitted presentation requested closed before onShow stays inactive while readiness completes, then dismisses before any replacement is admitted; hiding it before readiness can leave no native dismissal callback to await. Descendant admission and focus remain gated throughout that drain. Android does not promise that callback, so use the committed visible=false state and a cancellable frame barrier for handoff/focus, then prove the behavior under repeated open/close and replacement. No arbitrary sleep substitutes for native readiness. The [RN 0.86 Modal contract](https://reactnative.dev/docs/0.86/modal) routes Android Back through onRequestClose while suppressing BackHandler events; do not install a competing BackHandler listener. The IME may consume Back before the window receives it. Each delivered dismissal gesture requests one false transition; a controlled parent can decline it without being overridden or permanently locking later gestures.

Use transparent overFullScreen native windows with a dim backdrop, no sheet swipe dismissal and no transition animation in this first contract. Each window owns a safe-area provider. Native nesting and parent/child teardown are **unverified**: the first pass must prove Modal → Modal and Modal → Select on both installed platforms before AlertDialog/expanded propagation. If the pinned runtime cannot satisfy this chain, stop with the exact failing artifact and propose a different host/dependency contract; do not silently permit sibling windows, hide an ancestor's draft or add a portal dependency.

## Native Modal Surface

Preserve isOpen, defaultOpen and onOpenChange(boolean), with undefined isOpen selecting uncontrolled initialization and defaultOpen read once. Reject changing ownership mode. Preserve isDismissable=true for outside/backdrop interaction and isKeyboardDismissDisabled=false for Android system close and iOS accessibility escape; these are independent guards. Explicit Close/action controls remain usable when those gestures are blocked. Backdrop handling uses a separate sibling target so presses inside the panel never become outside presses. Covered ancestors do not handle a child's event.

Require a nonempty accessibilityLabel or aria-label, with the native prop taking precedence. Preserve titleText, closeButtonText, children, color, the five order names, rounded/orthogonal geometry, raised, numeric/native-percentage/auto width and height, customStyles, final style, customOverlayStyles and customDialogStyles. Forward the native panel View ref and native testID/data-testid alias. Preserve custom-children replacement of the starter composition; fallback content retains Modal Title, Placeholder text and Close Modal. Add optional native closeLabel for a complex fallback Close label; a nonempty string closeButtonText supplies the default name, and an otherwise unnamed rendered action is rejected. Custom content owns its own actions and names.

Add native-only isScrollable=true. A bounded internal scroller handles ordinary long content; callers set false when their custom content already owns a bounded FlatList or another scroller. Do not discover child types. Default panel width is min(400, available safe width), height follows content within the available window, and padding/scrolling replace the web starter's fixed 200 × 150 inner box. Explicit dimensions use native units and cannot claim safe target/content proof under caller-authored clipping. Reject nonfinite/negative dimensions and CSS units/functions.

The backdrop/window frame, panel and inner dialog remain distinct style owners. Computed dimensions/color → customStyles → final style controls the panel; customOverlayStyles controls the backdrop and customDialogStyles the inner dialog. Native root styles may carry color through the existing owned-content context, as Button does; authored child elements are not cloned. No-order surface/foreground use existing background/foreground roles. Ordered backgrounds use existing native action backgrounds; color overrides the computed background. Validate all supplied native style colors contextually. Rounded Modal uses one existing radius unit; raised uses the established native shadow recipe. DOM refs/classes/forms, labelled-by/described-by/details ID resolution, web DialogTrigger/slots, portal containers, entering/exiting flags and CSS animation/z-index behavior are excluded. Native dialogRole is excluded: use the dedicated AlertDialog and native content accessibility for the alert job instead of claiming DOM role equivalence.

## Native AlertDialog Surface

Compose the same private frame and ownership path rather than placing a second general Modal around it. Preserve the six type names, default info, required titleText/bodyText strings, ReactNode children after the body, showCancelAction=true, cancelAction/confirmAction, grouped labels and legacy visible-text aliases. Export matching component/Props/label/type aliases and the six constants plus the as-const available-type list. Require the same explicit native dialog name and validate rendered action names after resolving labels. Undefined/null AlertIcon retain default selection; supplied native nodes remain decorative. Recreate the six default status marks with core native Views/Text without an SVG dependency; record that rendering exception instead of copying SVG DOM elements.

Cancel/confirm invoke the corresponding callback once, then request closure. Backdrop/Back/escape and external state changes do not invoke those action callbacks. Preserve synchronous throw and non-awaited promise behavior. Pending state, dirty confirmation, async failure/retry, task cancellation and duplicate business mutation prevention remain workflow-owned; a controlled rejection of closure is not an async action manager. A caller needing custom pending actions can compose Modal with the existing pending Button contract.

Preserve ribbon, icon-circle, title/body and action-row presentation, using existing spacing/typography and twice the rounded radius unit for the AlertDialog panel. The inner dialog keeps its body and nonshrinking wrapping action row in a bounded scroller so both remain reachable when text scaling or the keyboard reduces the viewport. Actions can scroll with long content; this pass does not introduce a fixed footer. Root/backdrop/dialog styles retain the same merge owners. No fixed 400-pixel minimum, text shrinking or library font-scale cap may conceal overflow. Custom clipping remains an explicit authored constraint.

## Focus, Accessibility And Layout Proof

Add optional initialFocusRef and restoreFocusRef for native accessible targets. The default Modal composition and AlertDialog own a heading focus target; custom Modal content can supply its target or retain native-window initial focus behavior. Focus requests run only after the matching native presentation/readiness and are cancelled on closure, replacement, unmount or epoch change. Hosts supply refs belonging to the expected active ancestor/application; the provider guards ownership epochs and mounted targets without discovering arbitrary child/native-view ancestry. Do not restore focus while that ancestor is covered or closing. Library restoration requests accessibility focus rather than calling TextInput.focus merely to reopen the keyboard. Any native keyboard resumption must be measured and reflected in the viewport. Do not race the native window's own restoration with unconditional delayed focus.

Keep dialog content and actions as separate accessibility elements. Use native modal boundaries and hide covered ancestor content with the appropriate platform accessibility properties, without making the entire panel one accessible element. AlertDialog supplies important-text intent on its title without pretending a browser alertdialog role proves spoken output. The [RN accessibility contract](https://reactnative.dev/docs/0.86/accessibility) distinguishes modal sibling isolation from hiding a subtree; physical VoiceOver/TalkBack announcement/focus acceptance remains deferred. No hardware-Escape/focus-trap or screen-reader speech guarantee follows from mocked roles.

Reuse the verified keyboard policy: iOS padding, Android height, measurement-driven focused-field reveal, and no duplicate automatic keyboard insets. Compare panel/scroller/action frames against the physical window, safe areas and actual keyboard, not merely an oversized ancestor. Inspect portrait/landscape, normal and accessibility text, long bilingual title/body/actions, nested Select with keyboard, repeated close/reopen, controlled decline, ancestor/child teardown, context/draft retention and focus target removal. Default adjacent targets retain 44-point iOS/48-dp Android minima without overlap; explicit dimensions/clipped parents retain the established exception. Native coordination/focus dispatch and rendered hierarchies do not close physical touch/IME/ARM or owner visual acceptance.

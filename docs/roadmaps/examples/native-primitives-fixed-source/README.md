# Isolated Fixed-Source RN Primitives Trial

These non-shipping reproduction inputs implement [the approved four-pass trial](../../react-native-primitives-fixed-source-pass.md). They are not a workspace, production dependency or public Codon API. Keep Codon's source archive, palette, styling and controlled contracts unchanged. Shared React Native TypeScript remains the component implementation language; generated native projects and XCTest are inspection infrastructure.

`provenance.json` identifies the immutable upstream archive and checked Git blobs. `build.mjs` compiles only native TypeScript entry modules into ESM/CommonJS and strict declarations using the consumer's existing TypeScript 5.9.3. Relative ESM imports receive explicit .mjs suffixes. The existing consumer React types are bound only for declaration compilation; no runtime alias is used. The declaration build includes DOM types for upstream's existing web-shaped declarations, while the trial adapter retains its existing consumer compiler contract. No upstream tsup/development graph is installed. Private artifacts retain declared runtime/peer metadata, MIT notices, distinct file/hash/build identities and a private/non-publishing manifest. They do not claim web or publisher-build equivalence.

Run the builder with Node 24.15.0 and pnpm 10.18.3 available on PATH:

```sh
node build.mjs /absolute/upstream /absolute/consumer /absolute/new-output portal
```

The output must be new. Install the resulting file tarball into a fresh copy of the archived consumer, along with the approved react-dom 19.2.3 development peer, using scripts disabled and the existing seven-day release age. Freeze the resulting lockfile and verify peer/module identities before running tests. Feature builds resolve their existing declared dependency graph from the consumer; no added compiler dependency or Metro alias is required. Build metadata distinguishes artifacts but does not alter semver precedence, so hashes and file references are authoritative.

The original `portal-published.test.tsx` remains unchanged: it fails against the previously evaluated published Portal and must pass against the fixed artifact. `portal-lifecycle.test.tsx` adds edited-survivor, reverse-removal, host-isolation and cleanup cases. Preserve the published negative control in a separate consumer/result; do not count an expected failure as an accepted candidate test. The original App/style/mark/behavior examples are copied unchanged for the fixed-Portal-only checkpoint. Later source patches and adapter changes receive their own identities and receipts.

`host-managed-select.patch` applies cleanly to the pinned source and touches six files: the three native implementation/type pairs. It adds declarative Select visibility, accepted-transition geometry handling and native Content focus/Back/escape opt-outs. Apply it to a fresh upstream copy, then build Dialog, AlertDialog and Select separately with the same builder. Keep shared hooks/slot/types and fixed Portal unchanged. `primitive-contracts.tsx` supplies five positive and four negative declaration cases; `primitive-contracts.test.tsx` supplies ten state/interaction cases. The default primitive focus/dismissal behavior and the opt-out are tested separately, using real shared hooks and native focus/Back spies.

The versioned `App.tsx` is the next checkpoint, not the immutable fixed-Portal-only app. Its inline-window candidate uses controlled Codon trigger buttons and delegates focus/restoration to the existing host. It supplies controlled `open` to Select instead of synchronizing imperative trigger refs, preserves the private empty sentinel and typed keys, forwards disabled/read-only guards, deduplicates keys and resolves changed/removed collection labels. `trial.test.tsx` retains the prior seven cases and adds three adapter cases for read-only behavior, refreshed labels/same-key deduplication and authoritative removed keys. Layout/context/native inspection remains a separate gate; source tests do not certify the full-screen or physical interaction contract.

The context/layout follow-up adds an arbitrary nested form provider with live updates across successive windows, a controlled note readout and safe-area-aware numeric Select dimensions. The style helper overrides the general Modal host's percentage caps without modifying production Modal. The first geometry attempt and its 350-point panel remain historical evidence; corrected captures measure 390 points. The fixture still uses ScrollView and does not establish the production Select's variable-height FlatList/focus contract. An additional measurement-ref test verifies accepted external opening and stale callback rejection; the combined checked source inventory is 29 cases.

`make-typing-diagnostic.mjs` derives a separate instrumented app from the uninstrumented example, retaining the controlled owner and recording native text/event counts, callbacks, owner/host commits and focus/blur. It adds a raw native controlled TextInput as a labelled comparison. Generated outputs are private evidence, not a new shipped implementation. Use a fresh output path and keep the uninstrumented app/binary immutable; instrumentation can affect timing and cannot replace default-contract acceptance. The matched follow-up uses the same phrase with raw input first to address the original phrase/order confound.

`BaselineTypingApp.tsx` supplies a separate comparison using only the archived Codon public Modal, Select, AlertDialog, Input, Button and Text. It retains the parent/child/theme/selection/alert/typing choreography, with baseline-specific list/scroll identifiers. Copy it to the isolated entry App only for that variant; verify zero RN Primitives/Zustand sources in its actual native maps. A single comparison outcome is neither a broad reliability certification nor proof of the source of an intermittent failure.

Actual frozen consumer inputs, generated packages, both Metro maps, exact installed binaries, inspector inputs, native results and captured failures live in the new private evidence packet named in [the execution receipt](../../react-native-primitives-fixed-source-receipt.md). Earlier sealed packets remain read-only. Production adoption and long-term source/patch distribution require a subsequent decision.

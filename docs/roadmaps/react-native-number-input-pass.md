## Ownership And Dependency Decision

Recommend core native View, the existing native Input and Button, and private NumberInput state/arithmetic helpers. Keep Input/Button implementation unchanged; NumberInput owns composition, naming, numeric state and commits. Do not add a shared form, parser-provider or generic stepper framework, and do not implement the separate Stepper component incidentally.

Propose **one direct runtime dependency, `@internationalized/number` exactly 3.6.6, owned by packages/react-native**. This version is already installed and locked in the web graph; it is a candidate from that inspected graph, not a claim about the latest release. Its package declares Apache-2.0, no React/DOM peer, and `@swc/helpers: ^0.5.0`; the workspace currently resolves that helper to 0.5.2. The inspected utility source uses Intl and imports no React, browser DOM or native module. This still needs an installed Hermes gate: Node/browser results do not certify native ICU data or Metro resolution.

Use its public NumberParser and NumberFormatter exports, without importing React Aria, React Stately, their private helpers or Wavemap source. Declare the utility directly rather than relying on the web package's transitive installation. Future installation must preserve the existing release-age policy and unrelated lockfile resolutions, including the current helper resolution where compatible. No polyfill, Expo module, native linking change, peer upgrade or global Intl patch is included. If the exact utility or required Intl operations/locales fail the native gate, stop with that diagnostic and propose a remedy before adding dependencies or changing the locale contract.

The [official NumberParser contract](https://react-aria.adobe.com/internationalized/number/NumberParser) separates partial validation from parsing; [NumberFormatter](https://react-aria.adobe.com/internationalized/number/NumberFormatter) provides locale formatting over Intl. Recommend this utility over a bespoke locale parser. An ASCII-only dependency-free counterpart would exclude French decimal/group input and localized digits; delegating parse/format callbacks to every host would spread the field's core behavior into consumers. Neither alternative is the recommended first pass.

## Draft And Commit Transactions

Preserve the complete raw string while editing, including empty, minus/decimal prefixes, leading zeros, trailing separators, pasted invalid text and temporarily out-of-range numbers. Do not reformat or reject individual keystrokes, infer mutation from onKeyPress, or manufacture a value with Number(text)/parseFloat. This raw-draft rule is an explicit difference from web input filtering and avoids claiming that a JS character filter understands native composition. Hosts may observe drafts and explain errors; no native composition or physical IME acceptance is inferred from mocked events.

A transaction starts with native editing and ends with Return, end-editing, or an explicit step action. Read final text from onSubmitEditing.nativeEvent.text or onEndEditing.nativeEvent.text, with the latest native draft ref as fallback; do not rely on a render-delayed state closure. [RN TextInput documentation](https://reactnative.dev/docs/0.86/textinput#onendediting) identifies end-editing as the final-text event; blur can omit text. Forward native observers after the owned transition. Deduplicate submit plus end-editing for the same edit epoch so a normalized result is never committed again from a stale pre-normalization string. Blur alone updates focus/forwards its native event and does not invent another text payload.

| Commit input/outcome                                               | Result                                                                                                                                                                                            |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Empty or whitespace-only draft                                     | Request null; uncontrolled storage becomes empty. Emit onChange only if the stored/requested semantic value differs. Never convert blank text to zero.                                            |
| Valid complete decimal                                             | Validate, parse, normalize precision/bounds/optional step as specified below, then request the finite result once. Format the accepted value.                                                     |
| Nonempty partial, invalid syntax, non-finite or unsafe result      | Restore the currently authoritative formatted value, with no numeric callback. Raw edit observers have already received the attempted text. A lone minus/separator does not clear a stored value. |
| Same semantic value, including alternate spelling or negative zero | Format the authoritative value; no redundant numeric callback. Normalize negative zero to zero.                                                                                                   |
| Disabled/read-only takeover during an edit                         | Discard the uncommitted draft and cancel pending numeric mutation; do not commit from ensuing end/submit/press events. Preserve permitted native observation callbacks.                           |

For controlled values, a commit/step requests onChange but the displayed committed result waits for the parent value. If the parent declines or delays the update, return to the existing authoritative value; do not accumulate optimistic step requests. A changed external value, locale, formatting, bounds or step configuration cancels the current edit epoch and resets the draft from the authoritative value without emitting onChange. A same-valued rerender does not erase a draft. A host needing a same-value reset uses a keyed remount. Switching controlled/uncontrolled mode after mount is unsupported input. There is no timer-based echo window or implicit debouncing.

Value/defaultValue props remain authoritative and are never silently clamped or snapped on mount/config changes. A representable value outside the new bounds or off the configured grid stays visible until a user transaction normalizes it. This differs from the installed web snap path's eager normalization of supplied values and must be approved explicitly. It prevents prop updates from silently inventing host state or callbacks.

Step activation shares the same private transition function for touch and accessibility actions. Resolve from the latest draft once, without first publishing a separate blur/commit change. Keep an already focused editor focused rather than explicitly blurring/refocusing it; mark the edit transaction consumed so a redundant end event cannot undo the step. Guard takeover or cancelled gestures must suppress activation. One enabled press means at most one numeric request; hold-repeat, timers, acceleration and wheel/Arrow/Home/End interception are excluded from the first native pass.

## Locale, Precision And Numeric Domain

Recommend plain decimal formats only. formatOptions accepts `style?: "decimal"`, boolean useGrouping, minimumFractionDigits and maximumFractionDigits. Defaults are grouping enabled, minimum zero and maximum max(3, minimumFractionDigits). Require integer digit counts from zero through **six**, with minimum ≤ maximum. Reject unsupported options at runtime as well as in public types; currency, percent, unit, compact/scientific notation, significant-digit/rounding options and custom parser/formatter callbacks follow separately. This bounded decimal surface covers the screened consumers' configuration needs without claiming the full inherited web format contract or every possible consumer value range.

Let p be the resolved maximumFractionDigits. Numeric props must be finite, expressible at p decimal places and representable as safe integer decimal units at scale 10^p. Bounds must be ordered and step must be positive, nonzero in that domain and representable at the same precision. Invalid props/configuration fail with a contextual TypeError rather than silent rounding. Convert decimal strings to units without treating binary multiplication noise as extra precision. Guard every arithmetic intermediate; an unsafe proposed interaction is unavailable/rejected without numeric mutation. Raw text may contain extra fractional digits when p > 0; normalize those on commit with decimal half-expand rounding before integer-unit operations. With p=0, fractional syntax is invalid. No BigInt, arbitrary-precision or exact-financial-arithmetic promise is included.

Apply the parser's isValidPartialNumber check before parse at commit, then require a finite safe-domain complete result. Do not pass min/max into lexical validation: a negative/out-of-range draft can still be valid syntax and then be clamped. A partial string may pass the first check yet fail complete parsing, which restores the authoritative value. Locale separators are never guessed from another locale or replaced indiscriminately.

Read-only Node probes of installed 3.6.6 established the following cases; native Hermes still has to prove them:

| Locale / draft                                              | Inspected utility behavior                                      | Proposed handling                                                                                                               |
| ----------------------------------------------------------- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| en-US / `1,234.50`                                          | Partial validation passes; parses 1234.5                        | Accepted decimal, subject to configured precision/bounds.                                                                       |
| fr-CA / `1 234,50` (NBSP), fr-FR / `1 234,50` (narrow NBSP) | Parse 1234.5                                                    | Preserve raw edit, then format using the declared locale.                                                                       |
| en-US / `١٢٫٥`                                              | Detects Arabic numbering; parses 12.5                           | Accept when the native Intl gate passes, then format using the declared locale and its numbering-system extension/default.      |
| en-US / `1e3` or `0x10`                                     | parse alone returns 1000 or 16, but partial validation is false | Reject; the lexical gate prevents accepting exponent/hex input as decimal.                                                      |
| en-US / `-` or `.`                                          | Partial validation true; complete parse NaN                     | Keep while editing; restore authoritative value on commit.                                                                      |
| en-US / `+1`                                                | Default decimal validator rejects the plus prefix               | Reject; no signDisplay/plus-input extension is promised.                                                                        |
| en-US / `1,,2`                                              | Grouping-enabled validator accepts it and parser returns 12     | Retain the pinned utility's tolerant grouping policy, with an explicit regression case. This is not strict grouping validation. |

Accepting localized digits does not implicitly switch the host locale or output script; hosts choose a numbering-system locale extension when needed. The utility also interprets separators according to its detected numbering system: the inspected Arabic-digit string `١٢.٥` parses as 125, unlike `١٢٫٥`. Do not advertise cross-script separator guessing or silently rewrite it to a presumed decimal. Required installed coverage is en-US, fr-CA and fr-FR, plus localized-digit probes and explicit locale-extension behavior where supported. Validate locale syntax and supportedLocalesOf/resolved options; unsupported required locale/Intl capability stops the pass rather than silently falling back to en-US or introducing a polyfill. Host locale changes reset the edit epoch as above.

## Bounds And Step Rules

Use normalized integer decimal units for comparisons and grid arithmetic. First round a valid draft to p, then clamp to min/max. If step is explicitly supplied, snap to the nearest feasible grid point, anchored at minValue when supplied and zero otherwise. Halfway grid ties move away from the grid anchor. A maxValue between grid points does not become a new off-grid step: cap at the largest grid value ≤ maxValue. With step omitted, commits clamp but do not snap typed decimals; the buttons still use step 1. Bound/config changes alone emit nothing.

For a valid draft, increment chooses the next feasible step-grid value strictly greater than the normalized candidate; decrement chooses the next strictly smaller value. An out-of-range draft can move toward the range but cannot activate a direction with no feasible target. When the draft is empty or not parseable, the first increment seeds minValue if supplied, otherwise zero; the first decrement seeds maxValue if supplied, otherwise zero, projected onto the feasible grid. That first action returns the seed without adding another step. At a limit or unsafe candidate, the corresponding action is disabled and does not emit a change. canIncrement/canDecrement describe numeric feasibility; mutation guards are separate. Repeated 0.1 steps must not publish binary tails such as 0.30000000000000004.

| Configuration / action                                       | Expected result                                                                |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------ |
| No explicit step; commit `1.125` at default precision        | 1.125; subsequent increment selects 2 and decrement selects 1 from that draft. |
| step=0.1; committed 0.2; increment                           | 0.3 exactly in the supported decimal-unit model.                               |
| min=0.1, max=1, step=0.25; commit `0.475`                    | 0.6: grid is 0.1, 0.35, 0.6, 0.85; the halfway tie moves away from its anchor. |
| min=0, max=1.1, step=0.25; commit `1.1`                      | 1, the highest feasible grid value. Increment at 1 is quiet.                   |
| No min; step=0.25; commit `-0.125`                           | -0.25, the negative halfway tie away from zero.                                |
| min=1, max=10; empty increment / empty decrement             | 1 / 10, each as a single seed action.                                          |
| Controlled value=5, draft `8`, parent does not echo a commit | One request for 8; authoritative presentation returns to 5.                    |

## Native Composition, Styling And Accessibility

Render one native editor and two separately named Button targets inside nonaccessible View wrappers. Use horizontal flow with wrapping, growing the editor with text and moving controls onto additional rows when width is limited. Each actual interactive child retains the existing automatic 44-point iOS / 48-dp Android minima; measuring the composite root alone is insufficient. Do not transplant PageInput's 30-pixel height or stack two half-height native targets. Explicit authored constraints and clipped-parent/hit-slop exceptions retain their documented limits; do not silently shrink text or overlap neighboring targets to fit.

Preserve native editor semantics rather than marking the whole composite as one adjustable parent and hiding its children. Supplement the editor with owned custom accessibility actions named `incrementValue`/`decrementValue`, labelled with incrementLabel/decrementLabel, that call the same guarded step function; expose only available actions, and own their handlers so aliases cannot bypass disabled/read-only/bound guards. The two visible buttons remain usable independently. This first counterpart does not promise a web spinbutton's announcements or native adjustable swipe gesture. [RN accessibility actions](https://reactnative.dev/docs/0.86/accessibility#accessibility-actions) provide the native transport; synthetic action tests and installed traits do not certify VoiceOver/TalkBack speech. Physical acceptance remains deferred, without using that deferral to claim the component has been certified accessible.

Disable editor mutation and both actions under isDisabled/isReadOnly. Only disabled applies disabled presentation/focus blocking; read-only permits inspection/focus. At numeric bounds, disable only the unavailable step action. Compose read-only Buttons with an owned activation guard rather than setting Button.isDisabled solely for read-only, which would incorrectly dim them and block focus. Remove custom adjustment actions while guarded, and let host-supplied labels/hints explain read-only state. Apply disabled opacity once per branch, not by dimming the root and again dimming its children. Guarded synthetic callbacks must not mutate state. Hosts supply localized read-only/required/validation explanations; do not invent English accessibility strings or duplicate a formatted numeric range that hides the editor's actual draft.

Use native keyboard hints only. Recommend numbers-and-punctuation on iOS and numeric on Android, with an allowed inputProps.keyboardType override. No keyboard layout guarantees a minus, locale separator or Return key; a keyboard without Return still commits on native end-editing, and the showcase supplies an explicit blur/commit action. No inputMode precedence, custom keyboard module or hardware-key parser is added. Preserve full native event strings, selection events and uncapped font scaling by default.

Root native width/height, computed theme/validation/focus styles, customStyles and final style resolve in that order. customGroupStyles owns the inner wrapping layout; customInputStyles is TextStyle for the editor; customButtonStyles owns both step targets. Prevent child props from overriding numeric/guard handlers; only authored styles may impose explicit constraints. Group focus styling follows native focus within the three controls, without a focus-visible promise. Small/medium/large retain b11/b10/b9; geometry and error → warning → success priority follow Input. Callback state exposes authoritative value, inputValue, native focus/disabled/read-only/invalid flags, canIncrement/canDecrement and the post-custom defaultStyle, without a React Aria state object. isInvalid remains the host's errorState presentation, not an automatic schema verdict.

Reuse current control background/foreground/placeholder/border, validation borders, focus ring, spacing/radius and disabled-opacity roles. Draw default plus/minus with decorative core Views; undefined icons use those defaults and explicit null hides the glyph while preserving the labelled target. Authored icon content stays decorative. No SVG/animation package, new theme field, action ramp, generated palette or canonical color change is proposed.

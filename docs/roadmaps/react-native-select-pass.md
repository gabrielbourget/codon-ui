## Collection And Selection Contract

Recommend an explicit immutable data collection: required `items: readonly T[]`, `getKey(item): string | number`, `getTextValue(item): string` and optional `renderItem(item, state): ReactNode`. This native exception replaces arbitrary declarative children and one-shot Iterables with metadata that can be validated before rows are virtualized. It avoids walking or cloning arbitrary React children and inferring accessible names from rendered content. Default row content is getTextValue; authored content must be decorative within the row's one interactive/accessibility root.

Normalize keys with their type intact: numeric 0 differs from string "0". Reject duplicate keys, non-finite numeric keys and empty/whitespace text metadata with a descriptive development error; retain the same validation in production so invalid collections cannot silently select the wrong item. Keys remain stable across reorder and renderer changes. Snapshot the array for each render without mutating caller data. Optional `disabledKeys: readonly (string | number)[]` marks unavailable rows; unavailable keys outside the collection are harmless. Dynamic removal leaves the requested value intact but displays the placeholder until the key returns; it does not emit an automatic selection change. An existing disabled selected item still displays its label.

Preserve single controlled `value` or uncontrolled `defaultValue`, each key or null, and `onChange(nextKey)`; undefined value selects uncontrolled mode and null explicitly clears controlled selection. Initialize defaultValue once. Row activation requests one enabled key, then requests closure. Controlled output changes only after the owner echoes value. Cancellation never changes selection, and choosing the already-selected row closes without emitting a redundant change. No clear affordance is added; hosts can set value null.

Use `isOpen`, `defaultOpen` and `onOpenChange(boolean)` with the same controlled/uncontrolled boundary. Opening and closing are requests rather than forced mutations of controlled props. `isDisabled` prevents opening/activation; `isReadOnly` permits opening and inspecting the collection but suppresses selection. If disabled changes while open, request closure once and block selection even when a controlled owner keeps the modal visible. Keep selection/open state independent. Selection callbacks precede the close request, and unmounting during a callback must not trigger stale focus work.

Export `Select`, `ListBoxItem`, their Props aliases, typed native key/ref/render/style-state aliases, `SELECT_SIZE__SM`, `SELECT_SIZE__MD`, `SELECT_SIZE__LG` and `AVAILABLE_SELECT_SIZES` as const. Select forwards the trigger's native View ref. Select always creates the ListBoxItem interactive row root and passes selection/disabled/read-only flags explicitly; renderItem supplies its content. The public ListBoxItem is a controlled native Pressable row with required id/textValue, isSelected, isDisabled, isReadOnly, children and onPress, usable without a hidden collection context. Select owns activation and metadata on its rows; custom content cannot replace them. There is no separate row-local selection state or arbitrary child-registration API. Do not copy React Aria state objects, deprecated selectedItem render props, DOM events or CSS contracts into native types.

## Presentation And Lifecycle

Recommend a core React Native Modal with opaque, full-screen presentation and no animation for the first pass. It contains a heading, explicitly labeled Close button and virtualized FlatList. The modal uses existing theme background/foreground/control-border roles; no palette literals or theme fields are added. This gives long labels, large text and Android edge-to-edge windows a bounded viewport. A later anchored popover would need measured coordinates, clipping/flip rules, safe areas, keyboard and window changes; adopting that architecture now would broaden this pass. An OS picker is another alternative, but it adds a dependency and cannot retain the same authored row/style contract.

Use Modal's `onRequestClose` for Android Back and accessibility dismissal. BackHandler does not receive events while a modal is open. Close, selection and system dismissal share one close-request path; no dismiss-by-background behavior is needed for an opaque full-screen screen. Disable swipe dismissal and respect host-supported orientations. Use onShow to begin initial selected-row positioning/accessibility focus. iOS onDismiss can finish focus restoration; Android needs a bounded post-unmount/native-frame path because that callback is platform-specific. These are implementation requirements, not proof supplied by mocked tests. See [React Native 0.86 Modal](https://reactnative.dev/docs/0.86/modal).

Recommend adding `react-native-safe-area-context` **5.7.0 as an exact peer and development dependency of the native package**, matching the showcase's existing runtime pin. The modal owns a SafeAreaProvider and consumes its window insets; the host's outer provider alone may not describe a separate modal root. This is a deliberate native package dependency/consumer contract change requiring approval. It adds no upgrade to the host and no overlay library. Consumers must install the peer and perform normal native linking/build steps. An explicit caller-insets API would avoid this peer but shifts window correctness into each consumer; core SafeAreaView does not provide the required cross-platform contract. See [Expo SDK 57 safe-area-context guidance](https://docs.expo.dev/versions/v57.0.0/sdk/safe-area-context/).

FlatList keys use the typed key encoding; rows support dynamic height, wrapping and native font scaling. Do not use a fixed getItemLayout for variable text. Locate the selected row on opening, handle onScrollToIndexFailed with bounded measured retries and stop after unmount/closure. With no selected row, begin at the top. Empty collections show emptyListMessage and leave Close reachable. Verify offscreen selection near the end of a 200-item list, rotation, large text and modal reopening without duplicating callbacks.

## Labels, Styling And Native Exceptions

Require a nonempty `accessibilityLabel` or `aria-label` for Select, with established native precedence. The trigger owns button role, expanded/disabled state and the selected text or placeholder in accessibilityValue. The modal heading uses the same label. Require a localized `closeLabel`; preserve `emptyListMessage` default "No items remaining to select" and placeholder. Hosts supply localized read-only/validation hints. ListBoxItem owns radio role and checked/disabled state in this single-selection screen; a nonaccessible container preserves individually discoverable rows. Do not allow native/ARIA aliases to contradict owned semantics. Initial accessibility focus goes to the selected mounted row or heading; closure returns accessibility focus to the surviving trigger using the supported native ref API. Physical VoiceOver/TalkBack review remains deferred to application/device integration. See [RN AccessibilityInfo](https://reactnative.dev/docs/0.86/accessibilityinfo).

Touch targets retain the existing automatic 44-unit iOS/48-unit Android minima. Explicit host constraints remain exceptions. Item metadata supplies the accessible label even for custom visual children. Custom renderers must not nest another interactive control or override the row's accessible root. Primitive, array and Fragment text composition uses the established owned Text helper.

Preserve Select geometry, native DimensionValue width/height (including percentage widths, with finite numeric values and no CSS length strings), textSize small/medium/large mapped to b11/b10/b9, validation border priority error → warning → success, enableFocusStyle and offsetFocusRing. Style ownership is explicit: customStyles/final style belong to the root, customSelectedItemStyles to the trigger, customSelectedItemTextStyles to its owned selected text, and customOptionsListStyles to the list container. Root callback state includes open/disabled/read-only/invalid and post-custom defaultStyle. renderSelectedValue receives selectedItem or null, selectedText and isPlaceholder; omit React Stately state. ComponentIcon uses an owned native View/Text chevron by default, with explicit null hiding it. No animation dependency is added.

ListBoxItem preserves textSize and customStyles/final style; render state includes selected/pressed/hovered/focused/disabled/read-only and post-custom defaultStyle for callbacks. Use existing control hover/pressed/selected colors and validation/color processing. Disabled opacity and blocked callback behavior follow existing controls. Native placement and shouldFocusWrap props are excluded because this modal does not position an anchored popup or emulate web keyboard navigation. CSS classes/units, form submission, links, React Aria slots and obsolete key aliases are excluded. Hardware Arrow/Home/End/Escape/typeahead parity requires a separate supported native keyboard strategy; touch/assistive-technology activation and Android Back are the first acceptance scope.

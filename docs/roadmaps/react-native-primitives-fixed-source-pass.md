## Recommendation And Scope

Try the actual keyed Portal source first, without combining it with other fixes. Then evaluate narrowly scoped Select state and native interaction changes in private trial artifacts. Keep all production component source, repository dependencies/lockfile, theme defaults and tooling unchanged throughout the trial. A successful experiment prepares a migration recommendation; it does not install a fork into `packages/react-native` or authorize publication.

Use primitives inline inside the existing caller-owned native window as the contract-preserving candidate. Keep the provider-scoped root portal as a diagnostic comparison. Its known context change makes it ineligible for transparent adoption under the current contract; a passing key test or theme bridge does not change that. Accept partial adoption, or no adoption, if the remaining host and adapter work outweighs the infrastructure removed.

This is an explicit exception to the previous trial's published-packages-only boundary, limited to reproducible, non-shipping artifacts. It is not approval for an ongoing Codon fork. No Swift/Kotlin component implementation, new native module, animation/styling library, dependency upgrade, registry/CLI change, sibling-repo edit or release workflow is included.

## What The Source Fix Does

The [Portal 1.5.3 release](https://github.com/roninoss/rn-primitives/releases/tag/portal%401.5.3) points to upstream [`1bebe66b12e7ddd3c313226e0bc2ee02b6e78ab4`](https://github.com/roninoss/rn-primitives/tree/1bebe66b12e7ddd3c313226e0bc2ee02b6e78ab4). [Upstream change 124](https://github.com/roninoss/rn-primitives/pull/124) wraps each host entry in a fragment keyed by portal name. The pinned TypeScript has this fix; the previously integrity-verified published runtime does not. Registry metadata rechecked on 2026-10-15 still identifies 1.5.3 as Portal's latest stable version. A version label therefore cannot substitute for inspecting the emitted implementation.

The independent regression currently observes the second portal inheriting the first portal's state after removing the first entry. The fixed artifact must pass the same assertion, plus edited-survivor state, reverse removal, host isolation and complete cleanup. Run the published artifact as a separate expected-failure control; do not weaken its assertion, mark it accepted or overwrite the sealed original evidence. Keying entries addresses reconciliation identity. It does not change effect-based child transport, arbitrary context, native windows, Select popup ownership or focus behavior.

## Four Passes And Commit Cadence

Approval authorizes four coherent local commits, with narrowly scoped corrections committed at the affected boundary when needed. Commit completed work as each gate finishes; a failed gate gets an honest receipt instead of accumulating a broad unfinished diff. No push, PR, publication or external upstream message is included.

1. **Fixed-source provenance and identity.** Add reproduction/provenance/build inputs, build only fixed Portal, apply the explicit compatible DOM peer pin, prepare the frozen consumer and run identity/lifecycle tests against packed artifacts. Preserve published-failure controls. Produce both Metro source maps and a focused iOS replay of the previously failing sequence before attributing any improvement to later changes. Stop if the key gate fails; an unchanged text failure may proceed to the separately labelled ownership investigation.
2. **Controlled Select and one interaction owner.** Add the narrow Select state/type and three Content opt-out patches, private adapters and focused tests. Verify rejected/repeated popup requests, accepted-transition geometry, values/collections, action ordering, controlled triggers and host-managed focus/Back behavior. Pass strict consumer types, shared lint/format and tests before native propagation. Do not change production exports or install these artifacts into the repository workspace.
3. **Context, layout and iOS sequence diagnosis.** Complete the inline-window candidate and verify arbitrary nested context/live theme, retained state and full-screen Select geometry. Isolate the prior iOS text result against the unchanged baseline and the fixed-Portal-only checkpoint. Require three consecutive complete unpaced sequences on the same final Release binary, plus the dedicated parent/alert typing cases. If sequence integrity, context or one-owner behavior still fails, record the reproduction and stop before Android/full matrices rather than enlarging the patch set.
4. **Affected native gates and adoption receipt.** After source and iOS blockers pass, finish installed Intel iOS and Android checks one platform at a time: nesting in both directions, close/owner-removal/teardown, active-leaf dismissal, focus-target removal, normal/large text, portrait/landscape, keyboard/list/footer reachability and captures. Record source/archive/installed binary and embedded-map identities. Return a per-component go/no-go, proposed removable code versus retained host/patch cost, and an explicit next production dependency/maintenance decision. Restore normal text settings and stop task guests.

Source verification uses the independent Portal test, extended trial behavior/contract tests, strict consumer `tsc --noEmit`, shared ESLint/Prettier, frozen-install/peer/identity checks and both `expo export --source-maps` graphs. Run the unchanged native package checks only if later work touches it; the prior 309-test receipt remains baseline evidence. Preserve failures and corrected attempts with distinct identities. Native inspection uses existing lab tools and generated projects, without new SDKs, global authorization changes or signing setup. Physical touch/VoiceOver/TalkBack/IME/ARM and closer owner visual acceptance remain separately deferred to device/application integration.

## Source And Consumer Findings

The [versioned fixture source](examples/native-primitives-trial/README.md) compares a provider-scoped root portal with RN Primitives inside Codon's existing native-window host. The native package and maintained showcase runtime are unchanged. Pure typed style helpers and the existing Codon controls/status marks keep the established visual roles; this is neither a new styling system nor a production facade migration.

The fresh consumer installs the four approved exact trial packages and their declared closure using the existing seven-day release age, then uses a frozen lockfile with install scripts disabled. Its 781 baseline package records, including the local Codon archive, retain all existing versions/integrities. The trial has 831 records: fifty added packages through the primitive/shared/Zustand/Radix/web-peer closure. Twenty pre-existing snapshot records acquire or propagate new optional peer bindings; their bytes are not claimed unchanged. No existing native runtime/tool version is upgraded and Codon's repository lockfile/manifests remain unchanged.

The package manager automatically selects react-dom 19.3.0 through the web dependency graph, which requires React ^19.3.0 while the pinned consumer has React 19.2.3. This is a genuine peer mismatch in the trial install. It is not repaired through a React upgrade, extra direct dependency, override or peer-resolution policy change. One React, React Native and portal module identity is verified across the feature packages and Codon; the graph is still unsuitable for claiming a clean peer-compatible adoption. Future production packaging needs an explicit resolution decision.

Controlled selected values work through the trial adapter, including distinct numeric zero/string zero, rejected updates and an explicitly empty controlled value. The private empty sentinel prevents upstream undefined from switching to uncontrolled ownership. Explicit Trigger disabled forwarding resolves the previously observed root-disabled discrepancy in this fixture. Selection callbacks run before the explicit close by composing closeOnPress=false with the wrapper's close request. This does not supply upstream's missing declarative open/defaultOpen state input, and the trial does not silently remove Codon's open-state contract.

AlertDialog uses asChild with the action callback on the child Codon Button. Source tests verify callback/count/closure behavior with system dismissal blocked, while the earlier isolated throw-order probe remains applicable. The trial distinguishes explicit action closure from system closure locally; this adapter responsibility is not attributed to the upstream API. Portal/native-window composition preserves parent-local state while covered, and complete closure resets it. Root-portalled content receives host-context; the current native-window arrangement retains caller-local context. This confirmed difference remains an adoption gate, even though the diagnostic intentionally asserts the observed value and passes.

## Installed Diagnostics And Published-Artifact Follow-Up

The first iOS Release app builds in 312.87 seconds and its private XCTest harness builds in 20.05 seconds. The embedded map matches the same 48 archive, twelve primitive/Zustand and five trial/bootstrap sources; installed executable/JavaScript hashes match the build. The initial portal sequence reaches child/context/local-state/theme and controlled string-zero selection, then an immediate text assertion sees Native rather than Native alert note. The window sequence reaches caller-local context and retained state but finds no Select context inside a visibly blank panel. Both original failed cases and captures remain preserved, rather than being counted as accepted native checks.

A dedicated unchanged-binary typing comparison subsequently passes complete controlled phrases in both arrangements, for both the parent and alert fields. The first immediate-value failure therefore does not establish a general primitive typing defect; it remains an intermittent observation. The follow-up harness clips gestures to the keyboard-visible viewport and waits up to three seconds for the exact final value without pacing keystrokes. The window Select's missing flex fill is a prototype-layout issue; the one-line correction leaves Codon source/palette and every other trial behavior unchanged. Original source/native inputs stay separate from the corrected fixture.

Read-only inspection also confirms a release discrepancy: upstream [Portal 1.5.3 release notes](https://github.com/roninoss/rn-primitives/releases/tag/portal%401.5.3) describe keyed PortalHost entries, and the pinned source contains that fix, but the integrity-verified published .mjs/.js implementation and the installed native graph still use an unkeyed values array. The [new independent identity test](examples/native-primitives-trial/portal-published.test.tsx) removes one of two keyed callers and expects the surviving second entry to retain its own initial state. The published runtime instead returns first. The test fails with nine other consumer cases passing; it does not depend on Codon, a keyboard, a window shim or device-specific code. Both Metro native graphs contain that same published implementation.

This reproducible, platform-independent ownership failure blocks adoption of the evaluated release. No upstream patch, source fork, peer-policy workaround or production migration is applied. The trial stops before the full installed Android and larger-text/rotation matrices; further platform coverage cannot fix this JavaScript identity failure. A focused iOS follow-up will distinguish fixture corrections from candidate findings, then the final receipt will record the no-go decision, actual checked/skipped tiers and restored task guest. The source-only beta correction still passes types and the nine earlier behavior/composition cases; the new identity case remains deliberately failing. Its native Metro maps match the corrected source at 1,844,880 iOS and 1,848,824 Android bytes, with unchanged archive/runtime dependency identities.
